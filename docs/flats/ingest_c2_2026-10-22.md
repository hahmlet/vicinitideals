# Design districts chunk 2: ingest (2026-10-22)

Ingest only. No rule is encoded and no lot colour changes. Chunk 3 reads from here.
Branch `flats/ingest-c2`. All outlines are EPSG:2913 (Oregon North State Plane, feet), each
file carrying a `source` block (URL, layer, filter, fetched date, note). Raw downloads are not in git.

Status words: **fetched** = outline or text is in the repo. **map only** = the boundary exists only as a
picture; the PDF is stored with a `.map-only.json` beside it (status "map only, needs tracing", URL,
date, sha256) and has NOT been traced. **NOT FOUND** = looked, nothing usable.

Paths: outlines under `flats/config/areas/or/`; text under `flats/provenance/pending/or/` (see the next paragraph).

**Why the text is in `pending/`, not `docs/`.** The footnote, designation and cross-reference ledgers scan every
stored document and fail the suite until each footnote, designation and chapter is read and ruled (4 tests failed
when the 37 files were put in `docs/`: 7 unread Portland footnotes, 14 unruled designations, undeclared chapters).
That reading is encoding, so it is chunk 3's. The files are fetched by `flats.provenance.fetch` with its
usual `.meta.json` (URL, date, sha256). To bring one in: `git mv` the `.txt` and `.meta.json` to the same relative
path under `flats/provenance/docs/`, paste its block from `flats/provenance/pending/declarations.yaml` into the named
jurisdiction file's `code:` list, then rule what the ledgers ask. Until then the drift check cannot see them.
